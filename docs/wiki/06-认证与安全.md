# 06 认证与安全

## 1. 认证体系总览

项目**没有**使用 Spring Security 全套（仅引入 `spring-security-crypto` 用 BCrypt），认证完全由自定义实现：

```
前端登录 → 后端签发 JWT → 前端存 sessionStorage/localStorage
    │
    ├─ 每次请求：请求拦截器自动附加 headers.token
    │       ↓
    ├─ 后端 MyInterceptor 校验 JWT（免认证白名单除外）
    │       ↓
    └─ 每次登录/登录校验接口调用时后端刷新 token：
       新 token 放在响应头 updatedToken + Result.msg 中
       前端响应拦截器静默替换本地 token（滑动续期）
```

### 1.1 关键请求/响应头（非标准约定）

| 头 | 方向 | 取值 | 作用 |
| --- | --- | --- | --- |
| `token` | 请求 | JWT 字符串 | 身份凭证（**不是** `Authorization`） |
| `remember` | 请求 | "true"/"false" | 记住我：true 签发 7 天 token（`jwt.week`），否则短有效期（`jwt.expire`） |
| `frond` | 请求 | "true"/"false" | 前台场景标记（true 时登录接口允许普通客户通过；同时用于 update 接口区分前台改资料） |
| `code` | 请求 | 6 位验证码 | 注册/登录时邮箱验证码校验 |
| `contact` | 请求 | "true"/"false" | update 接口区分"改绑定信息"还是"改密码"场景 |
| `forgetPassword` | 请求 | "true"/"false" | 找回密码第二阶段标记 |
| `updatedToken` | **响应** | 新 JWT | token 滑动刷新（axios 读取需小写 `updatedtoken`；CORS 已 expose） |

以上自定义头均已加入 [WebMvcConfig](../../src/main/java/com/cloudland/config/WebMvcConfig.java) 的 CORS 允许列表。

## 2. JWT 细节

实现：[JwtUtils.java](../../src/main/java/com/cloudland/util/JwtUtils.java)，jjwt 0.9.1，HS256。

**Claims 内容**（见 `UserServiceImpl.buildTokenClaims`）：

| claim | 含义 |
| --- | --- |
| id | 用户 ID（拦截器据此查库） |
| phone | 手机号（token 登录时与库中比对） |
| username | 用户名 |
| power | 角色（0/1/2）——拦截器与库中比对检测权限变更 |
| debt | 欠款 |

**有效期**：

- `remember=true` → `jwt.week`（默认 604800000ms = 7 天）
- 否则 → `jwt.expire`（默认同为 7 天，可配置缩短）

**签名密钥**：`jwt.signKey`，默认 `change-me-in-production`，生产必须通过 `JWT_SIGN_KEY` 环境变量覆盖。

## 3. 拦截器 MyInterceptor

文件：[MyInterceptor.java](../../src/main/java/com/cloudland/Interceptor/MyInterceptor.java)

注册于 WebMvcConfig，拦截 `/**`。

### 3.1 免认证路径（excludePathPatterns）

| 路径 | 用途 |
| --- | --- |
| `/user/login`、`/user/register`、`/user/code`、`/user/forgetPassword` | 认证相关接口 |
| `/resource/**` | 静态文件（头像/土地文件/产品图） |
| `/land/page`、`/land/{id}` | 公开土地浏览 |
| `/product/page`、`/product/{id}` | 公开产品浏览 |
| `/msg`、`/msg/mail` | 公开留言与订阅 |
| `/alipay/notify`、`/alipay/return` | 支付宝回调（无 token 头） |
| `/error` | Spring 错误页 |

> 免认证路径全部为**精确路径匹配**（早期版本使用 URL `contains("login"/"register"/"code"/"forgetPassword")` 关键词放行，已因过于宽泛被移除）。

### 3.2 后台管理接口授权（ADMIN_RULES）

拦截器内置 `ADMIN_RULES` 集合（"METHOD servletPath" 精确匹配），命中则要求当前登录用户 **power ≥ 1**（员工/管理员），否则返回 403（响应头 `X-Forbidden-Reason: power`）：

| 模块 | 规则 |
| --- | --- |
| 用户管理 | `POST /user/page`、`POST /user/employee`、`POST /user/id`（按人查资料，含手机号/邮箱，前台无调用）、`DELETE /user` |
| 土地管理 | `POST /land`、`PUT /land`、`DELETE /land` |
| 产品管理 | `POST /product`、`PUT /product`、`DELETE /product` |
| 订单管理 | `POST /order/page`、`PUT /order`（后台退单）、`POST /order/download` |
| 消息管理 | `POST /msg/page`、`POST /msg/push` |

**前后台共享接口不在 ADMIN_RULES 中**，由 Service 层做归属校验（见 §3.4）。

### 3.3 用户上下文注入

认证通过后，拦截器将当前用户信息写入 request attribute，供 Controller/Service 做细粒度归属校验：

| attribute | 常量 | 含义 |
| --- | --- | --- |
| `currentUserId` | `MyInterceptor.ATTR_USER_ID` | 当前登录用户 ID |
| `currentUserPower` | `MyInterceptor.ATTR_USER_POWER` | 当前登录用户权限（0/1/2） |

### 3.4 Service 层归属校验（防越权）

| 接口 | 方法 | 校验规则 |
| --- | --- | --- |
| `DELETE /order/{id}` | `Order2ServiceImpl.deleteOrder` | power=0 仅能删除**本人**订单；power≥1 可删任意（后台能力） |
| `POST /order/order` | `Order2ServiceImpl.selectOrder` | power=0 强制只能查看**本人**订单 |
| `POST /order` | `Order2ServiceImpl.addOrder` | power=0 强制 uId=本人（不能替他人下单） |
| `POST /alipay/pay` | `Order2ServiceImpl.calcTotalAmount` + `saveTradeMapping` | **金额服务端重算**（忽略前端 totalAmount）：土地订单=land.price，产品订单=product.price×num，仅 status=0 订单可支付；power=0 只能支付**本人**订单 |
| `PUT /user` | `UserServiceImpl.update` | power=0 强制 id=本人，且**锁定 power/status/debt**（防自我提权）；前台（frond）仅验密码不改密，后台可直接重置密码 |
| `PUT /user/password` | `UserServiceImpl.updatePassword` | 前台自助改密：用户 ID **一律取登录态**（不信任请求体），验旧密码后仅更新 password 字段 |
| `DELETE /user/trolley/{id}` | `TrolleyServiceImpl.deleteTrolley` | power=0 仅能删除**本人**购物车条目 |

### 3.5 校验流程与 HTTP 状态码语义

| 检查 | 失败返回 |
| --- | --- |
| 无 token 头 | **401** |
| JWT 解析失败/缺 id claim | **401** |
| 用户不存在 | **401** |
| status=0 账号禁用 | **403**（`X-Forbidden-Reason: status`） |
| token.power ≠ DB power（权限已变更） | **402** |
| 后台接口且 power < 1 | **403**（`X-Forbidden-Reason: power`） |
| 校验通过 | 注入 currentUserId/currentUserPower 后放行 |

> **402 被复用为"权限变更"信号**，非标准 HTTP 语义。前端 [interceptor.js](../../vue/src/request/interceptor.js) 处理：401/402 清登录态跳首页；403 按 `X-Forbidden-Reason` 头区分——`power`（权限不足，仅提示）或 `status`（账号禁用，清登录态跳首页）。

## 4. 登录接口的双重职责

`POST /user/login`（[UserServiceImpl.loginUser](../../src/main/java/com/cloudland/service/impl/UserServiceImpl.java)）承担**密码登录**与 **token 校验/续期**两种功能：

```
请求带 token 头 且 user.password == null？
 ├─ 是 → token 模式：
 │      解析 JWT → id/phone 比对 DB → status 校验
 │      → (frond==true 或 power≥1) ? 签发新 token + 返回用户信息 : POWER_ERR
 └─ 否 → 密码模式：
        (可选) code 头 → Redis 校验邮箱验证码并删除
        → phone 查用户 → BCrypt 比对 → status 校验
        → (frond==true 或 power≥1) ? 签发 token : POWER_ERR
```

返回结构：`Result{ data: 用户信息(密码置null), code: 20005, msg: 新token }`。

前端三处消费该接口：

1. `utils/auth.js fetchCurrentUser()` — 页面加载恢复登录态
2. `utils/auth.js loginWithPassword()` — 显式登录
3. `router/index.js isUserLoggedIn()` — 路由守卫每次导航校验

## 5. 密码安全

- 存储：`BCryptPasswordEncoder`（WebMvcConfig 注册 Bean）
- 校验：`passwordEncoder.matches(raw, hashed)`
- 注册：明文加密后入库
- 前台改密：专用端点 `PUT /user/password`（`UpdatePasswordDTO{oldPassword, newPassword}`），用户 ID 取登录态、验旧密码、新旧查重
- 找回密码：邮箱验证码 + 一次性重置链接（Redis 5 分钟 TTL，用后即删）

## 6. 验证码机制（Redis）

| 场景 | Redis 键 | 值 | TTL | 说明 |
| --- | --- | --- | --- | --- |
| 注册/登录验证码 | 用户邮箱 | 6 位数字 | 5 分钟 | `/user/code` 发送，注册或登录时 `code` 头比对后删除 |
| 找回密码 | 用户手机号 | 6 位数字 | 5 分钟 | 邮件发送 `path+code-userId` 链接；落地页携带 code+userId 校验 |

验证码为 6 位随机数 `new Random().nextInt(899999) + 100000`。

### 6.1 万能验证码（测试便利功能）

`UserServiceImpl.isCodeValid()` 是全部验证码校验的统一入口，覆盖**登录、注册、找回密码**三个场景。配置项（application.yml `code.*`）：

| 配置 | 环境变量 | 默认 | 说明 |
| --- | --- | --- | --- |
| `code.master-enabled` | `CODE_MASTER_ENABLED` | yml 默认 `true`（本地开发）；**docker-compose 默认 `false`** | 万能码开关 |
| `code.master-value` | `CODE_MASTER_VALUE` | `000000` | 万能码值 |

- 开启时，验证码输入 `000000` 即可通过校验，无需查收真实邮件（每次触发会输出 WARN 日志便于审计）
- **生产环境必须设置 `CODE_MASTER_ENABLED=false`**（.env.example 已内置提醒）
- 找回密码场景用法：邮件链接格式为 `path+code-userId`，测试时直接手工拼 `/ForgetPassword/000000-{userId}` 即可进入重置页

## 7. 业务状态码体系

定义：后端 [Code.java](../../src/main/java/com/cloudland/controller/result/Code.java)，前端镜像 [code.js](../../vue/src/constants/code.js)。**两份必须同步维护。**

### 7.1 码段规划

| 码段 | 模块 |
| --- | --- |
| 0 / -1 | 通用成功/失败 |
| 10000-10999 | CRUD 操作 |
| 20000-20999 | 认证授权 |
| 30000-30999 | 邮件通知 |

### 7.2 常用状态码速查

| code | 常量 | 含义 |
| --- | --- | --- |
| 10001/10005 | ADD_OK / ADD_ERR | 添加成功/失败 |
| 10002/10006 | DELETE_OK / DELETE_ERR | 删除成功/失败 |
| 10003/10007 | UPDATE_OK / UPDATE_ERR | 修改成功/失败 |
| 10004/10008 | SELECT_OK / SELECT_ERR | 查询成功/失败 |
| 20001 | PHONE_NO_EXIST | 账号（手机号）不存在 |
| 20002 | PASSWORD_ERR | 密码错误 |
| 20003 | TOKEN_ERR | 令牌过期/无效 |
| 20004 | STATUS_ERR | 账号被禁用 |
| 20005 | LOGIN_OK | 登录成功 |
| 20006 | REGISTER_OK | 注册成功 |
| 20007 | PHONE_EXIST | 手机号已注册 |
| 20008 | POWER_ERR | 权限不足 |
| 20009 | LOGIN_RETURN | 请重新登录 |
| 20010 | PASSWORD_SAME | 新旧密码相同 |
| 20011 | UPDATE_SAME | 绑定信息相同 |
| 30001/30002 | SEND_MAIL_OK / ERR | 邮件发送成功/失败 |
| 30003 | CODE_ERR | 验证码错误 |
| 30004 | MAIL_EXIST | 邮箱已注册 |

### 7.3 HTTP 状态码 vs 业务状态码

| 层面 | 载体 | 处理位置 |
| --- | --- | --- |
| HTTP 状态码 | `error.response.status`（401/402/403/500） | 前端响应拦截器统一处理 |
| 业务状态码 | `response.data.code`（10001 等） | 各业务组件分支处理 |

**同一"账号禁用"会有两种表现**：拦截器拒绝时是 HTTP 403；登录接口内部校验时是业务码 20004。

## 8. CORS 配置

[WebMvcConfig.corsFilter()](../../src/main/java/com/cloudland/config/WebMvcConfig.java)：

- 允许源：`cors.allowed-origins`（默认 `http://localhost:8080,http://127.0.0.1:8080`，生产通过 `CORS_ALLOWED_ORIGINS` 配置）
- 允许方法：GET/POST/PUT/DELETE/OPTIONS
- 允许头：`token, Content-Type, remember, frond, code, contact, forgetPassword`
- 暴露头：`updatedToken`、`X-Forbidden-Reason`（供前端区分 403 原因）
- `maxAge: -1`（缓存预检）

## 9. 安全注意事项

1. **`application.yml` 与 `config/application-local.yml` 中的默认凭据仅限开发**：邮件密码、数据库密码直接写在配置里，生产必须用环境变量注入（docker-compose 已通过 `.env` 实现）
2. **JWT 密钥**：默认 `change-me-in-production`，生产必须改
3. **支付宝密钥**：沙箱网关 + 默认占位 key，生产需替换真实密钥与回调域名
4. `selectById` 类接口返回用户信息前会 `user.setPassword(null)`，但自定义 SQL 需注意不要把 password 查进 VO
5. 接口授权采用**两层防线**：拦截器 ADMIN_RULES 对 14 个纯后台管理接口要求 power≥1（见 §3.2）；前后台共享接口（删订单/下单/改资料等）由 Service 层做归属校验（见 §3.4）。前端路由守卫仅是第三道展示层防线，不作为安全边界
