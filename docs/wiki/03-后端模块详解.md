# 03 后端模块详解

后端代码位于 `src/main/java/com/cloudland/`。启动类 [CloudlandApplication.java](../../src/main/java/com/cloudland/CloudlandApplication.java) 开启了 `@EnableScheduling`（定时任务）与 `@MapperScan("com.cloudland.mapper")`。

## 1. Controller 层（REST 接口）

所有响应统一为 `Result` 对象：`{ data, code, msg }`。`code` 为业务状态码（见 [06-认证与安全](./06-认证与安全.md)）。后端 context-path 为 `/api`，实际 URL 前缀为 `http://host:9090/api/...`。

### 1.1 UserController — `/user`

文件：[UserController.java](../../src/main/java/com/cloudland/controller/UserController.java)
依赖：`UserServiceImpl`、`ITrolleyService`

| 端点 | 方法 | 说明 |
| --- | --- | --- |
| `POST /user/login` | `login(@RequestBody User, HttpServletRequest)` | 登录。**双模式**：带 `token` 头且无密码 → token 验证 + 刷新（返回新 token 于 `msg` 字段与 `updatedToken` 响应头）；带密码 → 密码登录（可附带 `code` 头做邮箱验证码校验）。`frond`/`remember` 头控制场景 |
| `POST /user/register` | `register(@RequestParam userIcon, @RequestParam user)` | 注册。`user` 是 JSON 字符串；头像可选，无头像时默认 `basic.png` |
| `DELETE /user` | `delete(@RequestBody Integer[] ids)` | 批量删除用户 |
| `PUT /user` | `update(@RequestParam userIcon, user, HttpServletRequest)` | 更新用户资料。`frond` 头为 true 时前台场景需验当前密码（身份确认）；**前台不通过本接口改密**（改密走 `PUT /user/password`）；后台（无 frond 头）可直接设置新密码 |
| `PUT /user/password` | `updatePassword(@RequestBody UpdatePasswordDTO)` | 前台自助修改密码。请求体 `{oldPassword, newPassword}`；用户 ID 取自登录态（防越权），验旧密码、新旧查重后仅更新 password 字段 |
| `POST /user/page` | `selectPage(pageNum, pageSize, user)` | 后台分页查询用户 |
| `POST /user/employee` | `selectAllId()` | 查询所有 `power=2` 管理员的 `id/username`（用于土地指派下拉） |
| `POST /user/id` | `selectById(@RequestBody Long id)` | 按 id 查用户（密码置 null 不返回） |
| `POST /user/code` | `sendCode(@RequestBody User)` | 发送 6 位邮箱验证码（Redis 5 分钟） |
| `POST /user/forgetPassword` | `forgetPassword(path, user)` | 找回密码。无 id → 发重置链接邮件；有 id + `forgetPassword:true` 头 → 校验链接中验证码后改密 |
| `POST /user/trolley` | `myTrolley(@RequestBody User)` | 查询我的购物车（带商品信息） |
| `POST /user/addTrolley` | `addTrolley(@RequestBody Trolley)` | 加入购物车 |
| `DELETE /user/trolley/{id}` | `deleteTrolley(id)` | 删除购物车条目 |

#### 1.1.1 密码修改的接口分工

- **前台自助改密**：专用端点 `PUT /user/password`（DTO：`pojo/dto/UpdatePasswordDTO.java`）。旧/新密码以 JSON 直传，用户 ID 从登录态取（防越权），验证旧密码后仅更新 password 字段
- **前台改绑定/资料**（`frond: true`）：`PUT /user` 中密码仅作身份确认，保留原密码哈希不修改
- **后台重置密码**（无 `frond` 头）：`PUT /user` 中 password 字段非空时直接 encode 覆盖

> 历史版本曾把新密码暂存在 `user.detailedAddress` 字段中转（字段语义被劫持），已随专用端点引入而移除。

## 2. Service 层

接口在 `service/`（`IUserService`、`ILandService`、`IProductService`、`IOrder2Service`、`ITrolleyService`、`IMsgService`、`IMsgSendService`），实现在 `service/impl/`。所有实现类继承 MyBatis-Plus 的 `ServiceImpl<M, T>`，天然获得 `save/list/getOne/updateById` 等单表方法。

### 2.1 UserServiceImpl（最复杂）

文件：[UserServiceImpl.java](../../src/main/java/com/cloudland/service/impl/UserServiceImpl.java)

| 方法 | 逻辑要点 |
| --- | --- |
| `loginUser(user, request)` | ① token 登录：解析 JWT → 取 `id/phone` claims → 比对 DB → 校验 status → `frond` 头为 true 或 power≥1 放行 → 生成新 token（remember 决定 7 天/短有效期）② 密码登录：可选验证码校验（`code` 头 + Redis 比对后删除）→ 手机号查用户 → BCrypt 比对 → status/权限校验 |
| `save(file, user)` | 注册：验证码校验（可选）→ 手机号/邮箱查重 → 头像落盘（或 basic.png）→ BCrypt 加密 → insert |
| `delete(ids)` | 删用户：删头像文件 → **先解除 land.employee_id 外键**（置 NULL）→ deleteBatchIds |
| `update(userIcon, user, request)` | 越权防护（power=0 锁定本人 + power/status/debt）→ 手机/邮箱查重 → 换头像删旧文件 → 分支处理密码：前台（frond）验当前密码后保留原哈希；后台 password 非空时直接 encode（重置密码） |
| `updatePassword(dto, request)` | 前台自助改密：用户 ID 取登录态 → 验旧密码 → 新旧查重 → 仅更新 password 字段 |
| `selectPage(...)` | 委托 `userMapper.selectByCondition`（XML 动态条件） |
| `sendOutEmail(user)` | 生成 6 位验证码 → Redis 存 5 分钟（键=邮箱）→ 发 HTML 邮件 |
| `forgetPassword(user, path)` | 两阶段：① 无 id：生成验证码存 Redis（键=手机号），发含 `path+code+userId` 重置链接的邮件 ② 有 id 且 `forgetPassword:true` 头：新密码与旧密码查重后加密更新 |
| `isCodeValid(redisKey, code)`（私有） | **统一验证码校验入口**：优先比对 Redis 真实验证码；若万能验证码开关开启（`code.master-enabled`，默认 `000000`）则直接通过并打 WARN 日志。`CodeCheck()` 公开方法委托至此，覆盖登录/注册/找回密码全部场景 |
| `buildTokenClaims(user)`（私有） | JWT claims：`id/phone/username/power/debt` |

### 2.4 Order2ServiceImpl（订单核心）

文件：[Order2ServiceImpl.java](../../src/main/java/com/cloudland/service/impl/Order2ServiceImpl.java)

| 方法 | 逻辑要点 |
| --- | --- |
| `selectPage(...)` | `num=-1`（土地单）走 `selectByCondition` 并补土地首图；否则走 `selectByCondition2`（产品单联用户表）。**两条 SQL 均过滤 `status != 0`——后台订单列表只展示已支付/已退单订单** |
| `selectOrder(user)` | 按 u_id 查 del=0 的订单（普通用户强制只能查本人），逐条组装 OrderVO（土地→LandVO+首图；产品→Product 信息） |
| `updateOrder(ids, status, time)` | `@Transactional` 批量改状态，可选写 payTime |
| `getOrder(response, order)` | Excel 导出：查询 → `OrderExporter.exportToExcel`（POI 写文件到存储根目录）→ `DownloadUtil.getFile` 流式响应 |
| `deleteOrder(id)` | 归属校验（power=0 仅能删本人订单）→ 已支付（status=1 且有 payTime）→ 软删 del=1；否则土地单回滚 status=1、产品单回滚库存 num，再物理删除 |
| `addOrder(order)` | `@Transactional`。归属校验（power=0 强制 uId=本人）。土地单：校验 status==1 可租 → 置 0 锁定；产品单：校验库存与 status → 扣减 num。设置 createTime/status=0/del=0 后 insert |
| `calcTotalAmount(orderIds)` | **支付金额服务端重算（防篡改）**：仅允许 status=0 未支付订单参与；土地订单=land.price，产品订单=product.price×num；订单/商品不存在或状态异常直接抛异常拒绝支付 |
| `saveTradeMapping(outTradeNo, orderIds)` | 归属校验（power=0 仅限本人订单）→ 交易号↔订单 ids JSON 存 Redis，键前缀 `alipay:trade:`，30 分钟 |
| `handlePaySuccess(outTradeNo)` | `@Transactional`。取映射 → `updateOrder(ids, 1, true)` 批量置已支付 → 删 Redis 键（幂等：键不存在直接 return） |

## 3. Mapper 层（数据访问）

接口位于 `mapper/`，均继承 `BaseMapper<T>`；自定义 SQL 在 `src/main/resources/com/cloudland/mapper/*.xml`。

| Mapper | 表 | 自定义 SQL（XML） |
| --- | --- | --- |
| `UserMapper` | user | `selectByCondition(page, user)`：动态条件（status/id/power/username 模糊）分页 |
| `LandMapper` | land | `selectByCondition(page, land)`：**三表联查** land ⋈ land_type ⋈ user×2（a_id→user_a 所有者、employee_id→user_b 代理人）；动态条件 + `id=-1`按价格/`id=-2`按面积排序；`selectById` 同联查单条。⚠️ 代理人为 INNER JOIN——**未指派代理人的土地不会出现在查询结果中** |
| `ProductMapper` | product | `selectByCondition(page, product)`：动态条件分页（联 user 取所有者信息） |
| `Order2Mapper` | order2 | `selectByCondition`（土地单联 land/user）、`selectByCondition2`（产品单联 product/user）、`selectOrder`/`selectOrder2`（导出用联查） |
| `TrolleyMapper` | trolley | 基本无自定义 SQL |
| `MsgMapper` | msg | `selectByCondition(page, msg)`：动态条件分页 |
| `MsgSendMapper` | msg_send | 无自定义 SQL |
| `CloudLandFileMapper` | cloudland_file | 无自定义 SQL（Service 用 QueryWrapper 直接查） |

> `LandMapper.selectByCondition` 是全项目最有代表性的 SQL：INNER JOIN 双别名自连接 user 表，同时取"所有者"和"代理人"信息，并在 `<where>` 中按非空字段动态拼接条件，`<choose>` 切换排序字段。

## 5. Interceptor：MyInterceptor

文件：[MyInterceptor.java](../../src/main/java/com/cloudland/Interceptor/MyInterceptor.java)

`preHandle` 流程（免认证路径已由 [WebMvcConfig](#41-webmvcconfig) 的 `excludePathPatterns` 排除，拦截器只处理需认证请求；早期版本在拦截器内用 URL `contains` 关键词放行，已因过于宽泛被移除）：

```
无 token 头 → 401 拒绝
        ↓
解析 JWT 失败 → 401
        ↓
claims.id 为空 → 401
        ↓
DB 查用户不存在 → 401
        ↓
status == 0（禁用）→ 403（响应头 X-Forbidden-Reason: status）
        ↓
token 中 power ≠ DB power（权限变更）→ 402
        ↓
注入 currentUserId / currentUserPower 到 request attribute（供 Service 归属校验）
        ↓
"METHOD servletPath" 命中 ADMIN_RULES 且 power < 1 → 403（响应头 X-Forbidden-Reason: power）
        ↓
放行（打 INFO 日志）
```

## 6. Util 层（工具类）

### 6.1 JwtUtils

文件：[JwtUtils.java](../../src/main/java/com/cloudland/util/JwtUtils.java)

- `generateJwt(claims, remember)`：HS256 签名；`remember=true` 用 `jwt.week`（7 天）有效期，否则 `jwt.expire`
- `parseJWT(jwt)`：验签并返回 Claims（`id/phone/username/power/debt`）

### 6.2 FileUtil

文件：[FileUtil.java](../../src/main/java/com/cloudland/util/FileUtil.java)
核心方法 `defineDirectory(parentId, landFiles, imageFiles, userIcon, productImg)`——按传入参数类型分流：

- **userIcon**：重命名 `userIcon_{UUID}{后缀}` 存 `UserIcon/`，返回 `[文件名]`
- **productImg**：重命名 `product_{UUID}{后缀}` 存 `Product/`，返回 `[文件名]`
- **土地文件**：资料文件存临时目录 `Land_{id}/CloudLandFile/` → **zip 压缩**为 `云用地_{id}{6位随机码}.zip` 放 `Land_{id}/` 下 → 删临时目录；图片重命名 `Img_{id}_{6位随机码}{后缀}` 存 `Images/`。返回 `[zip名, 图片名列表]`

辅助：`deleteFolder(File)`（递归删除）、`zipFolder`（递归打 zip）、`createDirectory`、`saveFiles`、`rename/rename2`（重命名规则）。

### 6.6 OrderClear（定时任务）

### 7.3 统一响应（controller/result）

- `Result`：`{ data, code, msg }` 三字段。**特殊约定**：登录接口把新 token 放在 `msg` 字段返回（同时也在 `updatedToken` 响应头）
- `Code`：业务状态码常量 + `isSuccess()`/`isFailure()` 工具方法（详见 [06-认证与安全](./06-认证与安全.md)）
- `Msg`：状态码对应的中文提示文本常量
