# 05 数据库设计

数据库：MySQL 8.0，库名 `cloudland`，字符集 utf8/utf8mb4。初始化脚本：[cloudland.sql](../../cloudland.sql)（建表 + 测试数据，Docker 首次启动自动导入）。

## 1. ER 关系图

```
                    ┌────────────┐
                    │ land_type  │ (字典表，6 种土地类型)
                    └─────┬──────┘
                          │ 1
                          │ (land.land_type → land_type.id, RESTRICT)
                          │ N
┌───────┐  1      N ┌────┴───────┐
│ user  │───────────│    land    │
│       │ (a_id)    │            │
│       │───────────│            │
│       │  1     N  │            │
└───┬───┘(employee_id, 可空)──────┘
    │               │ 1
    │               │ (cloudland_file.land_id → land.id, CASCADE)
    │               │ N
    │            ┌──┴──────────────┐
    │            │ cloudland_file  │ (土地的图片与资料zip)
    │            └─────────────────┘
    │ 1
    │ (order2.u_id → user.id, CASCADE)
    │ N
┌───┴──────┐        ┌──────────┐
│ order2   │        │ trolley  │ (u_id → user.id, CASCADE)
└──────────┘        └──────────┘
    p_id ──→ land.id 或 product.id（无外键，业务约定）

┌──────────┐        ┌──────────┐
│   msg    │        │ msg_send │ (订阅邮箱，独立)
└──────────┘        └──────────┘
                     ┌──────────┐
                     │ product  │ (a_id → user.id, CASCADE)
                     └──────────┘
```

**核心设计点**：

- `order2.p_id` / `trolley.p_id` 是**多态外键**：当 `num = -1` 时指向 `land.id`（土地订单），否则指向 `product.id`（产品订单，num 为数量）。数据库层不加外键，由业务层保证
- `land` 表对 user 表有**两个**外键：`a_id`（所有者）与 `employee_id`（代理人，可 NULL）
- `cloudland_file` 对 land 是 `ON DELETE CASCADE`——删土地自动删文件记录

## 2. 表结构详解

### 2.1 user — 用户表

| 字段 | 类型 | 约束/默认 | 说明 |
| --- | --- | --- | --- |
| id | int(11) | PK, AUTO_INCREMENT | 用户 ID |
| username | varchar(20) | NOT NULL | 用户名 |
| password | varchar(100) | NOT NULL | BCrypt 哈希 |
| age | int(11) | NOT NULL | 年龄 |
| phone | char(11) | NOT NULL, **UNIQUE** (`uk_user_phone`) | 手机号（登录账号） |
| address | varchar(25) | NOT NULL | 省市区码，逗号分隔（如 `110000,110100,110101`） |
| img | varchar(100) | DEFAULT 'basic.png' | 头像文件名（UserIcon 目录下） |
| power | int(1) | DEFAULT 0 | 0 客户 / 1 员工 / 2 管理员 |
| debt | double(10,2) | DEFAULT 0.00 | 欠款（写入 JWT claims） |
| detailed_address | varchar(255) | NOT NULL | 详细地址 |
| status | int(1) | DEFAULT 1 | 1 激活 / 0 禁用 |
| mail | varchar(255) | NOT NULL, **UNIQUE** (`uk_user_mail`) | 邮箱 |

### 2.2 land_type — 土地类型字典

| id | type_name | 说明 |
| --- | --- | --- |
| 1 | 农用地 | 耕地、林地、草地、农田水利用地、养殖水面等 |
| 2 | 建设用地 | 城乡住宅、公共设施、工矿、交通水利、旅游、军事设施等 |
| 3 | 商业用地 | 商店、粮店、饮食店、公园、游乐场、影剧院、体育场馆等 |
| 4 | 公共管理与公共服务用地 | 党政机关、社会团体、教育科研文化卫生体育、公共绿地等 |
| 5 | 水域及水利设施用地 | 河流、湖泊、水库、渠道等 |
| 6 | 其他土地 | - |

### 2.3 land — 土地表

| 字段 | 类型 | 约束/默认 | 说明 |
| --- | --- | --- | --- |
| id | int(11) | PK, AUTO_INCREMENT | 土地 ID |
| land_name | varchar(25) | NOT NULL | 名称 |
| land_type | int(10) | DEFAULT 1, FK→land_type.id (RESTRICT), 索引 `idx_land_type` | 类型 |
| description | varchar(500) | DEFAULT '无' | 描述 |
| address | varchar(50) | NOT NULL, 索引 `idx_land_address` | 位置（省市区码） |
| ordered | int(5) | DEFAULT 100 | 排序权重 |
| price | double(10,2) | DEFAULT 0.00 | 价格（元/平方米/天） |
| a_id | int(10) | NOT NULL, FK→user.id (RESTRICT), 索引 | 所有者 ID |
| status | int(5) | DEFAULT 0 | **1 可租用 / 0 已占用**（已租出或被未支付订单锁定） |
| area | double(25,2) | DEFAULT 0.00 | 面积（㎡） |
| employee_id | int(11) | NULL, FK→user.id (RESTRICT), 索引 | 代理人（删用户时后端先置 NULL） |
| detailed_address | varchar(255) | NULL | 详细地址 |

外键：`fk_land_land_type`、`fk_land_employee`、`fk_land_upload_user`，全部 `ON DELETE RESTRICT ON UPDATE RESTRICT`。

> **status 语义说明**：`land.status` 中 **1=可租用、0=已占用**（与"默认 0=正常"的直觉相反，建表注释只写"状态"）。[Order2ServiceImpl.addOrder](../../src/main/java/com/cloudland/service/impl/Order2ServiceImpl.java) 校验 `status==1` 才允许下单、下单后置 0 锁定；`deleteOrder`/`OrderClear` 回滚时置回 1。注意**列默认值为 0**——后台新增土地时若不选状态，入库即"已占用"；后台表单的状态下拉仅 power=2 可见。

### 2.4 cloudland_file — 土地文件表

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | int(11) | PK, AUTO_INCREMENT | |
| path | varchar(255) | NOT NULL | 文件名（相对 `Land_{id}/` 目录） |
| land_id | int(11) | NOT NULL, FK→land.id (**CASCADE**), 索引 | 所属土地 |
| type | int(1) | NOT NULL | **0 = 图片文件 / 1 = 用地资料 zip** |

磁盘布局：`{FILE_STORAGE_ROOT}/LandFile/Land_{land_id}/` 下放 `云用地_{id}{随机码}.zip`（type=1）与 `Images/Img_{id}_{code}.{ext}`（type=0）。

### 2.5 product — 产品表

| 字段 | 类型 | 约束/默认 | 说明 |
| --- | --- | --- | --- |
| id | int(11) | PK, AUTO_INCREMENT | |
| product_name | varchar(25) | NOT NULL | 产品名 |
| description | varchar(255) | NOT NULL | 描述 |
| ordered | int(255) | NOT NULL | 排序权重 |
| price | double(10,2) | NOT NULL | 单价 |
| status | int(1) | DEFAULT 0 | 上架状态 |
| a_id | int(10) | DEFAULT 1, FK→user.id (**CASCADE**), 索引 | 所有者 |
| num | double(10,2) | NOT NULL | 库存（下单扣减、退单回滚） |
| img | varchar(255) | NOT NULL | 图片文件名（Product 目录下） |

### 2.6 order2 — 订单表

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | int(11) | PK, AUTO_INCREMENT | 订单号 |
| p_id | int(11) | NULL | 多态：土地 id 或产品 id |
| num | int(11) | NULL | **-1 = 土地订单**；正数 = 产品数量 |
| u_id | int(11) | FK→user.id (**CASCADE**), 索引 | 下单用户 |

### 2.7 trolley — 购物车表

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | int(11) | PK, AUTO_INCREMENT | |

| num | int(11) | NULL | -1 = 土地 / 正数 = 产品数量 |

### 2.8 msg — 留言表

| 字段 | 类型 | 说明 |

## 3. 外键约束汇总

| 约束名 | 子表.字段 | 父表.字段 | 删除行为 |
| --- | --- | --- | --- |
| fk_land_land_type | land.land_type | land_type.id | RESTRICT |
| fk_land_employee | land.employee_id | user.id | RESTRICT |
| fk_land_upload_user | land.a_id | user.id | RESTRICT |
| fk_cloudland_file_land | cloudland_file.land_id | land.id | **CASCADE** |
| fk_product_user | product.a_id | user.id | **CASCADE** |
| fk_order2_user | order2.u_id | user.id | **CASCADE** |
| fk_trolley_user | trolley.u_id | user.id | **CASCADE** |

> 注意：`land` 的两个 user 外键是 RESTRICT——所以后端 `UserServiceImpl.delete` 必须先把 `land.employee_id` 置 NULL 才能删用户（`a_id` 引用的土地需先处理，RESTRICT 会阻止仍有土地的用户被删除）。

## 4. 索引清单

| 表 | 索引 | 字段 |
| --- | --- | --- |
| user | uk_user_phone (UNIQUE) | phone |
| user | uk_user_mail (UNIQUE) | mail |
| land | idx_land_type / idx_land_address / idx_land_employee_id / idx_land_a_id | 对应字段 |
| cloudland_file | idx_cloudland_file_land_id | land_id |
| product | idx_product_a_id | a_id |
| order2 | idx_order2_u_id | u_id |
| trolley | idx_trolley_u_id / idx_trolley_p_id | u_id / p_id |

## 5. 初始化数据说明

`cloudland.sql` 自带测试数据（user 9 条、land 6 条、product 6 条、order2 11 条等），包含一个 `id=1` 的占位用户（power=2）。**生产环境建议初始化后清理测试数据并修改默认密码。**
